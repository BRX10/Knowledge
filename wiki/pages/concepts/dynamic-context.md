# Dynamic context

Four properties distinguish dynamic context from a prompt:

- **Assembled, not written.** The agent selects the bases it needs, guided by their charters, and combines them at the point of use. A cross-functional question draws on several domains without a global model negotiated upfront.
- **Governed at the source.** What enters the context has an owner, a date and a status. A quarantined page simply does not appear.
- **Rights follow the person.** An agent sees what the person it serves is allowed to see, no more.
- **Traceable.** Every element points back to a page, and every page to its sources and its owner ([[traceability]]).

It requires standard access: open protocols such as the [[model-context-protocol]] let any agent query any base in the same way. The protocol may change; the principle will remain.

> This is where principle zero pays off. Dynamic context is the consumption plane at its most demanding. It is only as reliable as the management plane behind it.
